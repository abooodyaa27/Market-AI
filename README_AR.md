# Market AI V2.1

تطبيق Android لتحليل Gold (XAUUSD) وBitcoin (BTCUSD) بصورة مستقلة، مع سجل محلي للإشارات المرصودة. لا تداول آلي ولا OpenAI API داخل التطبيق.

## منطق الإصدار 2.1.0

التسلسل ثابت: H4 Macro Bias → H1 Executive Structure → M15 Opportunity → M5 Setup → M1 Trigger.

- **H4 (15 نقطة):** سياق عام؛ التوافق يمنح النقاط، والمحايد لا يمنع الدخول. التعارض القوي يمنع الصفقة: اتجاه معاكس مع بنية/كسر مؤكد، ميل EMA20 بثلاث شموع لا يقل عن 0.15 ATR، وفصل EMA20/50 لا يقل عن 0.3 ATR.
- **H1 (25 نقطة):** اتجاه EMA20/50 وميل واضح مع سوينغات مؤكدة أو كسر بنية في الاتجاه نفسه. هذا هو الاتجاه التنفيذي الإلزامي.
- **M15 (20 نقطة):** PULLBACK إلى أحدث POI صالحة من سوينغ ضمن آخر 30 شمعة؛ عرض المنطقة لا يتجاوز ATR. أو CONTINUATION عند تجميع آخر أربع شموع بعرض ≤2 ATR وحركة صافية ≤ATR، يتضمن تصحيحاً مع بقاء اتجاه EMA20/50 وقرب السعر من التجميع وEMA20. مسار الاستمرار لا يشترط POI عميقة.
- **M5 (20 نقطة):** لمس المنطقة ثم جسم مغلق اتجاهي ≥0.1 ATR، تقدم عن الإغلاق السابق وبقاء في جهة EMA20، ومدى ≤2 ATR.
- **M1 (20 نقطة):** كسر مغلق لآخر خمس شموع بأكثر من 0.05 ATR، جسم ≥0.15 ATR ومدى ≤1.8 ATR. السعر يبقى في جهة الكسر وعلى مسافة ≤0.5 ATR من إغلاق التفعيل، لمنع المطاردة.

BUY/SELL يتطلب H1 واضحاً ومسار M15 صالحاً وM5/M1 مؤكدين ودرجة ≥70 دون تعارض قوي من H4. بأوزان ثنائية للمراحل، تحقق المتطلبات يعطي 85 أو 100؛ الدرجة ليست احتمال نجاح. H4 المحايد يفتح فرصاً كان V2 يمنعها، والاستمرار يضيف مسار دخول جديداً، دون ادعاء زيادة مثبتة في العائد أو معدل الإشارات الحية.

التحليل للشموع المغلقة فقط، بحد أدنى 55 لكل إطار، وATR14. يلزم آخر إغلاق مؤكد، واستمرارية نافذة M1/M5. فجوات الإغلاق التاريخية على الأطر العليا لا تمنع التحليل. لا فلتر ساعات أو Sessions. وقف خلف آخر خمس شموع M1 بهامش 0.2 ATR ومخاطرة بين 0.5 و3 ATR؛ الأهداف 1R/1.75R/2.5R. WAIT يعيد مستويات null ويعرض — و«لا توجد صفقة حالياً» مع السبب.

## البيانات والواجهة

المصدر biquote.io، والأسعار خارجية وقد تختلف عن وسيط التداول. تحديث السعر والشمعة الحالية كل ثانية أثناء تشغيل التطبيق دون تغيير الشموع المغلقة. جلب الشموع كل 30 ثانية أو خمس ثوانٍ عند انتظار إغلاق الدقيقة. فشل أصل لا يمنع الآخر.

السعر يتقادم بعد خمس ثوانٍ من الاستلام أو عشر ثوانٍ من وقت المصدر إن توفر، والفريم بعد 90 ثانية من التحديث. السوق المغلق أو غير المفتوح صراحة يمنع الإشارة. عدم توفر توقيت المصدر معروض في الواجهة؛ حينها تقاس حداثة الاستلام فقط. عرض H1/H4 ملائم للجوال مع تفاصيل باللمس.

## Signal History وسياسة القياس

كل إشارة مؤكدة للأصلين تُسجّل تلقائياً مرة واحدة، حتى إذا كانت شاشة الأصل الآخر محددة؛ WAIT لا يسجل. Signal ID = إصدار المنطق + الأصل + BUY/SELL + وقت شمعة M1 المغلقة. تغير السعر أو نوع المسار داخل التفعيل نفسه لا يكرر الإشارة. المستويات وحالات المراحل والدرجة وATR وPOI تثبت عند التسجيل.

يحفظ السجل في localStorage داخل WebView ويبقى بعد إغلاق التطبيق. تُحفظ الأهداف المرصودة وأوقات الوصول إليها، ووقت الإغلاق وسببه، وأقصى حركة لصالح/ضد الإشارة بوحدات السعر وR، والمدة. لا توجد بيانات تجريبية في سجل الإنتاج.

سياسة `observed-ticks-30m-v1`:

- TP1 وTP2 محطتان أثناء ACTIVE، وتستمر المتابعة حتى TP3 أو SL أو 30 دقيقة أو انعكاس H1 مؤكد أحدث من التفعيل. الهدف هو قياس الوصول إلى الأهداف الثلاثة دون افتراض خروج جزئي.
- النتائج تأتي من أسعار مرصودة لاحقة؛ لا تُستنتج من قمم/قيعان شموع قد تخفي ترتيب SL/TP. السعر المرصود هو سعر الإغلاق التقييمي الفعلي، لذلك R قد يتجاوز مستوى الهدف/الوقف عند قفزة سعرية.
- أول مشاهدة بعد حد الصلاحية تغلق EXPIRED بالسعر والوقت المرصودين، ولا تنسب أهدافاً جديدة بعد انتهاء الصلاحية.
- انقطاع المشاهدة أكثر من عشر ثوانٍ، بما في ذلك إغلاق التطبيق، يغلق INVALIDATED / DATA_GAP مع نتيجة R مجهولة. لا خدمة متابعة في الخلفية ولا إعادة بناء لترتيب الأسعار المفقودة. السجل القديم يبقى محفوظاً، لكن المتابعة الحية تحتاج التطبيق مفتوحاً واتصالاً متاحاً.
- فساد السجل يوقف الإضافة ويحافظ على البيانات الخام للتصدير JSON. فشل الحفظ يظهر تحذيراً؛ لا يُحذف التاريخ تلقائياً.

الإحصائيات تفصل الأصل ونوع الفرصة وإصدار المنطق:

- Win Rate = نسبة النتائج المغلقة ذات R موجب، من جميع المغلقة ذات R معلوم، بما فيها انتهاء الصلاحية/الإبطال المرصود.
- متوسط R = متوسط النتائج المغلقة ذات R معلوم؛ النتائج المجهولة مستبعدة.
- نسب TP1/TP2/TP3 وSL = مرات الوصول المرصودة / جميع الإشارات المسجلة، بما فيها النشطة والمجهولة. TP1 ثم SL يسجل وصول TP1 مع نتيجة نهائية SL.

هذه قياسات إشارات وليست صفقات منفذة؛ لا رسوم أو سبريد تنفيذ أو انزلاق محسوب. لا تُعد اختبارات الصحة دليلاً على الربحية.

زرّا CSV وJSON يصدّران جميع السجلات مع إصدارها والسياسة، بغض النظر عن فلاتر العرض. Android يستخدم نافذة النظام لاختيار ملف دون أذونات تخزين عامة. ملف التصدير المعلّق محفوظ داخلياً لاستعادة نافذة الحفظ بعد إعادة إنشاء Activity. السجل لا يُرسل إلى خادم.

لا تتغير قواعد 2.1.0 أو سياسة قياسها أثناء جمع النتائج؛ أي تغيير لاحق يستلزم إصداراً واضحاً جديداً، مع الاحتفاظ بإصدار كل سجل للمقارنة.

## الاختبارات والبناء

`npm test` لاختبارات التحليل والسجل والحفظ والتكرار والنتائج. `npm install && npx playwright install chromium && npm run test:ui` لاختبار الواجهة الفعلية بمقاسات 320/390/430، BUY/SELL/WAIT، فصل الأصول، السجل والإحصائيات والتصدير وإعادة الفتح باستخدام أسعار اختبارية.

GitHub Actions يشغّل الاختبارات قبل assembleDebug وlintDebug وفحص التوقيع. Artifact: `Market_AI_V2_1.apk`، وArtifact منفصل لتقارير الفحص وصور الواجهة. اختبار المتصفح يحاكي حجم الهاتف وجسر التصدير، ولا يغني عن اختبار نافذة حفظ Android على جهاز فعلي.

versionCode 3 / versionName 2.1. مفتاح التوقيع التجريبي يستخدم cache V2 نفسه؛ حذف cache قد يغيره. يلزم مفتاح إصدار دائم خارج المستودع للتوزيع الإنتاجي.
